# 初一食午營運管理系統（Vercel 版）

本專案目前以本機優先運作，整合三個功能：

- `salary_app/`：員工出勤、時薪／月薪、加班、獎金扣款與薪資結算。
- `accounting/`：每日收入支出、日薪工讀生與正式員工薪資帶入。
- `dashboard_cost/`：收入、成本、人事費與月度損益分析。

分析頁的每張圖表右上角都有「JPG」按鈕，可直接儲存含標題、分析期間與匯出日期的圖片，方便傳送或留存。

月薪員工可建立「特殊加班起算規則」，依生效期間、每月日期範圍與星期改用不同的正常上班起點；當日臨時班別仍具有最高優先權。

## 本次營運強化

- 薪資月結新增每日狀態、建議月休確認、獎金扣款確認與月結前阻擋檢查。
- 已鎖定薪資重新開啟後，會保留更正原因、操作人、原始總額及補發／追回差額。
- 記帳可建立每月固定收支、保存壓縮後的收據照片、彙整供應商，並核對每日現金與非現金入帳；新增複製昨日／上週、手機快速新增與最近常用項目。
- 記帳分類可重新命名、搬移、停用或合併；匯入別名及常用付款方式也可在畫面維護。
- 記帳新增每日關帳、月底檢查、月份鎖定、操作軌跡、上一動復原，以及瀏覽器內安全快照與版本還原。
- 收入支出分析新增跨系統異常中心、月增年增、平台占比、每萬元營收人事費、成本目標與供應商異動；指標、月份圖、支出結構、收入來源、人事圖與損益表可點回記帳或薪資明細。
- 薪資、記帳與分析會共用目前檢視月份；桌機採一致的左側選單，手機改為抽屜選單與單欄閱讀。
- 三個系統透過 `shared/operations-store.js` 共用薪資與記帳摘要，避免各頁各算一套數字。
- `pnpm run check` 會以老闆固定月薪、何秀芷特殊加班與月休、時薪國定假日、缺勤扣薪及分鐘加班案例進行回歸測試。

## 本機啟動

雙擊專案根目錄的 `START_BREAKFAST.bat`。系統會啟動本機伺服器並開啟：

`http://127.0.0.1:4173/`

三個功能應由同一網址與同一瀏覽器開啟，才能共用薪資與記帳資料。若要使用 Gemini 打卡辨識，可將 `.env.example` 複製為 `.env.local`，再設定 `GEMINI_API_KEY`；`.env.local` 不可上傳到 GitHub。

## 記帳資料規則

- 已匯入 2022 年 1 月至 2025 年 12 月歷史營收、營業支出、薪資及出勤；2022 年 1–10 月使用舊版逐月資料，11 月起使用新版年度活頁簿。
- 已由 `初一食午營業額新版(2026年).xlsm` 匯入 2026 年 1–7 月營收及營業支出。
- 正式員工薪資以薪資管理系統為唯一來源，匯入時不重複採用 Excel 的薪資列。
- 週末或臨時日薪人員獨立記錄，可選每日 1,000 元、1,500 元或自訂金額。
- Uber 與 foodpanda 採原始平台淨收入資料重建，避免重複計入現金營收。
- 原始 Excel 的 2 月與 4 月日明細支出，分別比年報表快照多 1,300 元與 2,150 元；系統採日明細，並在畫面顯示提醒。

## 資料保存與備份

本機操作仍會先寫入瀏覽器 `localStorage`，安全快照另存於 `IndexedDB`，因此網路暫時中斷時仍能繼續使用。登入正式網站後，薪資與記帳資料會在最後一次修改 60 秒後同步到 Vercel Private Blob；伺服器使用版本號與 Blob ETag 防止兩台裝置互相覆蓋，遇到衝突時會停止自動寫入並要求選擇版本。每次更新前會保留每日雲端備份，薪資月結另保留月份快照。

員工核對連結存放於 Private Blob，只有持有隨機連結的人可查看該份明細及回覆；連結預設 7 天到期。仍建議月底下載一次薪資與記帳 JSON 備份，作為不依賴任何雲端平台的最後救援副本。

## 檢查與建置

```powershell
pnpm run check
pnpm run build
```

`check` 會檢查前端 JavaScript、Vercel Functions 與薪資／記帳回歸案例；`build` 會產生 Vercel 要發布的 `public/` 靜態網站。

## Vercel 上線設定

1. 在 Vercel 建立 Blob Store，選擇 Private，並連結到本專案。Vercel 會自動提供 `BLOB_READ_WRITE_TOKEN`。
2. 建立 Sign in with Vercel App，Callback URL 設為 `https://你的正式網域/api/auth/callback`。
3. 在 Project Settings → Environment Variables 設定：
   - `VERCEL_APP_CLIENT_ID`、`VERCEL_APP_CLIENT_SECRET`
   - `VERCEL_ALLOWED_EMAILS`：允許登入的 Email，使用逗號分隔
   - `VERCEL_OWNER_EMAILS`：可以強制覆蓋雲端版本的擁有者 Email
   - `SESSION_SECRET`：至少 32 個字元的隨機字串
   - `GEMINI_API_KEY`（若要使用 AI 打卡辨識）
4. Framework Preset 選 `Other`。本專案的 `vercel.json` 已指定 `pnpm run build` 與輸出資料夾 `public`，不要再把 Output Directory 手動設成其他名稱。
5. 上傳前，先在目前本機系統分別下載「薪資 JSON 備份」與「記帳 JSON 備份」。Vercel 網域與 `127.0.0.1` 的瀏覽器資料彼此不共用，因此部署後要先在 Vercel 網站還原這兩份 JSON，再登入 Vercel 雲端；若雲端尚無資料，系統就會把還原後的完整資料建立為第一版。若雲端已有資料，載入前會先建立本機安全快照。
